# TV 角色、声优、制作人员详情页设计

版本：v2，2026-09-09。状态：已实施，包含 2026-09-09 的按钮精简及关联作品横版卡片要求。本版取代上一版“两类页面”的方案。

## 三个 route，共用一套 layout

| 独立导航入口 | 共享数据源 | 页面下方 section，按顺序 |
| --- | --- | --- |
| `CharacterDetailsRoute(characterId)` | 角色详情、关联作品、角色讨论 | 声优 → 出演作品 |
| `VoiceActorDetailsRoute(personId)` | 人物详情、出演记录、参与作品、人物讨论 | 出演角色 → 参与作品 |
| `StaffDetailsRoute(personId)` | 人物详情、参与作品、人物讨论 | 参与作品 |

以上 route 名称用于设计说明，最终命名遵循现有导航约定。三个入口都渲染同一个 `PeopleDetailsLayout`，共用首屏、介绍阅读层、评论弹窗、横向 section、焦点与滚动规范。数据决定 section 内容，布局不分叉成三份。

角色页的声优头像打开声优 route；条目页的制作人员头像打开制作人员 route；出演角色头像打开角色 route。同一个人可能兼有配音与幕后职业，入口明确决定 route，异步加载到的职业数据不改变当前页面类型。

声优与制作人员虽然共享人物 API，但保存独立的导航状态；同一人物 ID 的两个 route 不能混用焦点与滚动记录。

## 共用首屏

首屏只组织身份、大图、介绍入口、讨论入口与轻量操作；各类关联列表都位于完整首屏下方。

- 背景由当前角色/人物图片放大模糊，叠加条目详情页同款深色渐变。
- 左上角类型文字依次为“角色”“声优”“制作人员”；下方为大标题、不同于标题的原名、职业或类型及可用计数。
- 左侧并排显示介绍和讨论两张卡片，右侧展示约 3:4 的清晰图片。机构图片完整适配。
- 介绍卡片直接复用条目详情页的 `TvDetailsDescriptionCard`，标题为“角色介绍”“声优介绍”或“制作人员介绍”。图标、字号、留白、描边和“显示更多”位置沿用同一组件，正文显示两行摘要。
- 讨论卡片显示数量和一条真实评论摘要，标明来自用户讨论。没有讨论时保留入口，显示“暂无讨论”。
- 卡片整体是一个焦点目标；聚焦时描边变白，右上圆形箭头切换为白底深色箭头。不单独聚焦箭头，不放大卡片。
- 下方仅保留“查看大图”胶囊操作。作品已在下方 section 显示，不再放“浏览出演作品 / 浏览参与作品”按钮。
- 清晰头像随首屏一起滚走，下方 section 占用整页宽度，不被右侧图片挤成窄列。

建议以 960 × 540 dp 为基准：左右 58 dp 安全边距，标题约 40 sp，原名 19 sp，辅助信息 15–16 sp，按钮高 40 dp。右侧图片约 210 × 280 dp，两张介绍/讨论卡片约 268 × 116 dp。首屏高度随名称长度和字体大小适配，正常字号时底部露出第一节标题与列表上缘。

## 下方 section

所有 section 在同一个纵向页面里，内部列表横向滚动。

### 角色：声优 → 出演作品

“声优”使用圆形演员头像与姓名。读取跨作品去重的演员列表；若有来源作品上下文，可优先呈现该作品关联声优。只有一人就展示一人，不补空头像。不猜测演员的语言或配音版本。

“出演作品”使用现有作品封面、作品名称和该作品里的主角/配角等定位，点击进入条目详情页。

### 声优：出演角色 → 参与作品

“出演角色”使用圆形角色头像、角色名、所属作品名称，点击进入角色 route。同一个角色在不同作品中的出演记录可以分别展示，使用角色 ID 与作品 ID 的组合键。

“参与作品”使用作品封面、作品名称和服务返回的职位，点击进入条目详情页。记录数量不等同于去重后的角色数量。

### 制作人员：参与作品

直接显示“参与作品”，使用横版卡片显示作品封面、作品名称和导演、分镜、演出等实际职位。多职位组合在卡内标题上方，长文本适当截断。

此 route 不插入声优或出演角色 section；个人、公司与团体共用该呈现方式。

### 共同行为

- 头像沿用现有圆形人物卡；所有关联作品使用条目详情页同款 16:9 横版卡片（宽 198dp），将 API 已有封面裁切展示，不假设存在额外剧照、年份或评分。
- 列表标题随所在 section 获焦由 16 sp 动画到 26 sp；卡片和头像采用统一描边，不缩放。
- 纵向切换区块时平滑定位；横向分页按稳定业务 ID 恢复焦点。
- 已完成加载的空列表隐藏 section；加载状态和失败重试保留在本节，不把失败解释成无内容。
- 主页面底部不再重复基础信息，也不另设讨论列表 section。基础资料在介绍里阅读，评论从讨论卡片进入弹窗。

## 介绍展开：全文 → 基础信息 map

点击任一种介绍卡片，复用条目详细介绍的全屏模糊阅读布局。

从上往下为：

1. 固定标题“角色介绍 / 声优介绍 / 制作人员介绍”和较弱的姓名。
2. 可滚动的完整介绍文字。
3. 介绍结束后显示“基础信息”及 key/value 表。
4. 与正文相同的底部留白和滚动渐隐。

正文与基础信息在同一个 vertical scroll column。基础信息显示为两列：左列较窄的字段名，右列较宽的字段值，按 infobox 顺序自然排列。不是标签 chip，也不拆成多个信息卡片。长别名、网址和多值可换行，不截断关键信息；缺失字段直接省略。

人物/角色没有条目标签数据，因此不凭职业或类型制造标签行。默认聚焦整块阅读区域，上下键滚动，显示右侧滚动条及边缘渐隐；阅读区不逐行争抢焦点。返回恢复介绍卡片的焦点。

介绍为空但存在基础信息时，介绍卡片仍可进入，并直接呈现基础信息；介绍和资料均缺失时显示明确的空状态。后续数据补齐不抢走焦点。

## 讨论入口：播放页同款居中弹窗

点击讨论卡片，保持当前 profile 页面和滚动位置，在当前窗口中打开 `TvOptionModal`。后方页面压暗但仍可识别；不进入条目 Review 页式的全屏评论界面。

### 列表态

- 默认宽 480 dp，高度随内容变化，最多 460 dp，留足四周视野；窄屏或大字体时受可用视口约束。
- 深色表面、20 dp 圆角、浅描边、24 dp 内边距，沿用播放页现有弹窗参数。
- 顶部“讨论”，下方是姓名与评论数量，再接分隔线。
- 中间为独立纵向分页列表。评论卡包含头像、作者、来源、时间和 2–3 行摘要；每条是一个焦点目标。
- 人物/角色评论不显示作品评分、星星或评分分布。
- 默认聚焦第一条可用评论；上下移动平滑滚动，尽量把焦点条目放到列表中部，首尾受边界约束。
- 空列表显示空状态；错误显示可聚焦重试，追加失败保留已有内容。
- 模态期间屏蔽后方页面的焦点、触摸和按键；返回关闭弹窗并恢复讨论卡片。

### 全文态

按确认后在同一个弹窗中切换到该评论全文：

- 标题区显示作者和来源/时间，中间阅读完整富文本，保留剧透遮罩。
- 评论支持的操作放在固定底部操作区，复用已有评论详情的胶囊 action 风格与来源能力判断。
- 保持单个模态表面，不在列表上再叠一个弹窗或新的全屏阅读页面。
- 返回先回评论列表，恢复原评论和列表位置；再返回关闭弹窗。
- 真实删除或数据重排时优先恢复相邻的稳定业务 ID。

现有 playback 的共享能力是 modal 容器和评论卡/全文样式。把整个 profile 讨论列表放进这个容器、以及列表/全文在容器内切换，是本次设计新增的组合方式，不宣称现有播放页已经这样实现。

### 动画与数量

- 打开/关闭沿用现有模态淡入淡出风格；头像背景不重新加载或单独 crossfade。
- 列表和全文切换可用短淡入过渡，外层弹窗保持稳定宽度。
- 混合来源分页的 total 如果仅为已加载下界，显示“已加载数量+”；分页结束后才显示确数。缺失数值不按 0 显示。

## 焦点与返回

| 操作 | 结果 |
| --- | --- |
| 首次进入三个 route | 聚焦介绍卡片 |
| 首屏左右 | 介绍与讨论卡片之间，或操作按钮之间移动 |
| 首屏向下 | 操作行，再到第一节真实内容 |
| section 上下 | 按顺序移动，恢复该节之前的条目 |
| 介绍返回 | 关闭阅读层，恢复介绍卡片 |
| 评论全文返回 | 在同一弹窗内回列表 |
| 评论列表返回 | 关闭弹窗，恢复讨论卡片 |
| 大图返回 | 关闭图片查看，恢复查看大图按钮 |
| profile 之间往返 | 各自恢复首屏/section、横向位置和业务 ID |
| 从下方 section 返回 | 先回首屏介绍卡片；首屏默认入口再次返回交给 route 导航 |

焦点准备复用布局附着、窗口与生命周期事件，不用固定延时。用户主动移动焦点后，后台加载完成不得再次执行首次默认送焦。主页面和弹窗各自持有滚动状态，仅最上层消费返回键。

## 数据核对与实现边界

现有共享仓库已经提供设计所需数据，无需新增服务器接口：

- `PersonDetailsRepository.characterDetailsFlow`、`characterSubjectsPager`
- `PersonDetailsRepository.personDetailsFlow`、`personWorksPager`、`personCastsPager`
- `PersonCommentRepository.commentsPager`
- `CharacterDetailsInfo`、`PersonDetailsInfo`、`CharacterSubjectInfo`、`PersonCastInfo`、`PersonWorkInfo`

字段约束：

- `CharacterDetailsInfo.role` 是角色/机体/舰船/组织等实体类型；主角/配角是 `CharacterSubjectInfo.role`。
- 职业使用 `PersonDetailsInfo.career`，已知值本地化。
- `collects` 是公开收藏人数；不表示当前用户是否收藏这个人。
- `castCount` 是角色与作品组合的出演记录；`workCount` 是去重作品数。
- 基础 map 来自 `infobox`，不预设必有性别、生日、身高或网站。
- TV 使用独立 `TvPeopleDetailsViewModel` 和 `TvPeopleDetailsUiState`，保留演员、出演角色、作品职位、角色定位与讨论所需的完整字段。
- 声优和 staff 复用人物仓库，route 参数包含明确类型；页面与模态的焦点、滚动状态保留在 UI 层。
- 使用现有 window 内 Compose 模态设施，不使用 Android `Dialog` 或新窗口。
