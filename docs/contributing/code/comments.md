# 评论

Ani 的剧集评论与人物、角色评论混合两个来源：Ani 自有评论和 Bangumi 的评论。
每条评论有一个带来源前缀的稳定 ID（`ani:` 或 `bangumi:`），列表、投票、举报与评论详情都用它定位一条评论，不区分来源。

Ani 评论可以回复、贴纸回应、点赞点踩和举报；Bangumi 评论只读，可以在 Bangumi 打开。
楼中楼回复与根评论一样可以投票，但回复没有自己的回复数，也不能再被展开。

## 评论详情

评论列表里一条评论最多显示两条简要回复。点评论的回复块（简要回复或“展开 N 条回复”）打开它的评论详情（thread）：
根评论在上，下面是时间正序的全部回复，底部是回复栏。详情里根评论与回复共用同一份乐观更新状态，
在列表里点过的赞、加过的贴纸进详情后仍然显示，反过来也一样。

### 原地打开与独立页面

播放页评论栏和人物页评论 sheet 里的详情不是新页面，而是在评论列表的位置上原地切换：播放不被打断，sheet 也不用关掉再开。
打开的详情由 view model 持有，转屏不丢；自动连播或页内切集后列表换成另一集的，还开着的详情一并关掉；
人物评论 sheet 关闭时也关掉详情，下次打开 sheet 是列表。

只有从通知进入才用独立路由（`CommentThread`）。它自带举报与编辑器状态，顶栏副标题是评论所在的条目与剧集或人物名，
右上角可以前往评论所在的页面。路由参数是稳定 ID，所以 Bangumi 评论的详情也能从通知进入。

### 系统返回

原地打开的详情要让系统返回（Android 返回手势和返回键、桌面端 Esc）先关掉详情，而不是离开页面。
宿主在渲染详情的位置注册一个返回处理器：它比页面自己的返回处理晚注册，所以详情打开时优先生效；
详情关掉后处理器失效，返回又交回页面。全屏播放时宿主让出返回，由播放器先退出全屏，详情留在那里。

### 回复对象

回复栏默认回复根评论。点某条回复把回复对象切到它，回复栏上方出现可清除的“回复 @某人”标记，点根评论或清除标记回到根评论。
编辑器标题也显示“回复 @某人”。回复了另一条回复的回复在作者名旁标“回复 @某人”；被回复的那条已删除时显示“回复 已删除的评论”。

回复按时间正序排列，分页用“创建时间 + 稳定 ID”的游标，所以列表加载过程中有人新发回复不会导致重复或漏掉。
新回复在末尾，发送成功后详情重新加载并滚到末尾，让用户看到自己的回复；发送后评论列表也刷新，根评论的回复数随之更新。

### 根评论的加载

从列表进入时先显示列表里的那条根评论（含简要回复），同时请求服务端的最新版本并替换。
请求失败时继续显示快照并提示一次；没有快照（独立路由）时显示错误卡，可重试。根评论不存在、已删除或不属于这个对象时显示“评论不存在或已被删除”。

Bangumi 评论的回复一次全部返回。Bangumi 不可用时服务端返回 503，详情按加载失败处理。

### 通知落地

回复通知带着根评论和那条回复的稳定 ID。打开详情后向后翻页找到那条回复（最多翻 10 页），滚到它并高亮一下；
找不到（已删除或太靠后）时停在根评论。
