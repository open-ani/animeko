# 功能开关

功能开关让服务端决定一个功能对某个用户是否启用，客户端不用发版就能灰度、抽样或紧急关闭。
服务端的分发规则（全量、按用户固定分桶、每次请求随机、客户端随机、仅名单，以及平台与版本条件）在后台配置，见 `ani-api-server/docs/feature-flags.md`。
本文说明客户端怎样拉取和使用开关。

## 模型

- `FeatureFlag`（`app/shared/app-data/.../domain/featureflag/`）枚举了客户端认识的开关：开关名 `key` 与后台配置一致，`default` 是服务端没有配置、
  或还没有拉取到值时的行为。响应里没有的开关用默认值，所以后台删除一个开关等于让客户端回到默认行为；后台停用则所有人都收到 `false`。
- 服务端返回的每个值是 `FeatureFlagValue(enabled, threshold)`：`enabled` 是本次请求的值；`threshold`（0..1）只在「客户端随机」策略下出现，
  表示服务端不抽签、由客户端每次使用时按这个概率抽。本版本不认识的开关也随快照保存，但没有 `FeatureFlag` 项就没人读它。
- 抽签封装在 `FeatureFlagManager` 里：`isEnabled` 对客户端随机的开关每次调用独立抽一次，`flow` 在服务端的值每次变化时抽一次；
  `enabled == false` 时不抽（总开关、关闭名单、平台 / 版本条件仍然有效）。业务代码只拿布尔值，不自己随机。

## 拉取

`FeatureFlagManager` 在应用启动时由 Koin 创建并 `start()`：

1. 先用上次拉取并保存的快照（`dataStores.featureFlagStore`），这样启动早期读取的值与上次一致，而不是先按默认值跑一会儿。
2. 等登录状态确定（`SessionStateProvider.stateFlow` 发出第一个值，即 token 刷新完成）后请求 `GET /v2/feature-flags`。
   请求带 Ani token 与安装 ID：服务端对登录用户按用户 id 固定分桶并应用名单，对未登录的请求按安装 ID 分桶。
3. 之后每当身份变化（登录、退出、换用户）再拉取一次。固定分桶的开关在登录前后可能得到不同的值，这是预期行为。
4. 失败按 5 秒、30 秒、2 分钟重试，用尽后沿用快照或默认值，直到下次身份变化。

一次启动内，服务端的值只在拉取成功时变化。消费者应在用到时调用 `isEnabled`，或用 `flow(flag)` 观察；
像播放会话这样的短生命周期对象在创建时读一次，让一次会话内的行为一致。对客户端随机的开关，这个「读一次」就是随机的单位：
每个播放会话读一次，就是按播放会话抽样；要按启动抽样，后台改用「每次请求随机」策略即可，客户端代码不变。

快照不放进设置备份：固定分桶的结果属于这台设备或这个用户。

## 新增一个开关

1. 在 `FeatureFlag` 加一项，写清默认值的含义。
2. 在用到的地方注入 `FeatureFlagManager`，调用 `isEnabled` 或 `flow`。
3. 在后台「功能开关」页创建同名开关并配置策略；创建前客户端按默认值行为。按事件抽样用「客户端随机」，按用户灰度用「固定分桶」。

## 现有开关

| 开关 | 默认 | 作用 |
|---|---|---|
| `play_flow_analytics` | `true` | 是否向 Analytics 发送播放加载流程埋点 `play_flow`（见 [播放加载流程埋点](analytics-play-flow.md)）。每个播放会话读一次，后台用「客户端随机」即可按播放会话抽样。关闭时调试悬浮窗照常显示。 |
